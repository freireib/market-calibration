REPRODUCIBILITY

Methods & data.

Which study is selected?

The 2026 Primaries study uses each candidate's individual YES contract. A primary with ten candidate contracts contributes ten binary events per horizon, not ten independent elections. The displayed mean Brier and reliability diagrams are contract-level diagnostics; a complete multicategory event Brier score needs a separate normalization and event-level analysis. The 2026 General Election study treats each race as one binary Democratic-win event.

What is scored?

Each row represents a specific binary contract at a fixed time before the outcome. A Brier loss is (probability − outcome)², where outcome is 0 or 1. Only called, certified, or settled outcomes are eligible; an uncalled race is never scored.

Isochronic snapshots

The general-election study uses September 3, October 3, and November 2 at 3:00 p.m. Eastern before November 3. Primary forecasts use two calendar months, one calendar month, seven days, and one day before each contest's actual election or runoff date, at 3 p.m. Eastern. Quotes must precede their respective cutoff.

Calibration bins and uncertainty

Use 5%, 10%, 20%, or 25% probability bins. You can hide bins containing fewer than a selected number of contract observations. Each visible point shows the mean quoted probability and observed event frequency. The point-size counts and approximately 95% Wilson intervals are based on displayed bins; Kish effective sample size is used when volume-weighted. Correlated outcomes can make those intervals too narrow. Hiding low-count bins changes the reliability diagram only; Brier scores still include all eligible contracts.

Volume

The default gives each binary contract equal weight. You can include only contracts trading at least a minimum number of contracts or no more than a maximum number in the seven days before each snapshot. A volume threshold excludes records without a known pre-snapshot volume. These are volume units in contracts, not dollars. Limits apply to all charts, scores, and the market table, including the matched-cohort comparison. They remove high-volume observations from the sample; they do not establish whether trading manipulation occurred. Optional weighting by volume or its square root is a distinct choice.

Missing data and comparability

Missing, stale, or invalid probabilities are excluded, not imputed. Turn on “Matched-race cohort only” to compare the same resolved races at all three horizons. Source coverage and gaps must be inspected before publishing conclusions.

Refresh without reloading

The Refresh data button requests the most recent JSON already published on GitHub Pages and updates the chart while preserving your filter selections. It does not trigger the Kalshi API collector; to get newer settled results first run the appropriate GitHub Actions collection workflow.

Bring your own dataset

Upload a local JSON dataset using the published schema. Data is handled in your browser only; uploads do not modify the repository.
